# 段位分析：输入、计算与边界

本模块用于四人日本麻将半庄的 **what-if 局面比较**。同一套输入分别进入 Python 与浏览器 TypeScript 引擎；两者返回相同结构。这里的启发式顺位模型独立于 [TingQue.ai](https://tingque.ai/) 的牌谱 AI、第一打模拟、手牌逆推与陪练模型。

## 输入契约

```json
{"kyoku_idx":0,"honba":0,"kyotaku":0,"scores":[25000,25000,25000,25000],"table":"特上","dan":"四段"}
```

| 字段 | 含义与校验 |
| --- | --- |
| `kyoku_idx` | 整数 0–11；东1–东4为0–3，南1–南4为4–7，西1–西4为8–11 |
| `honba` | 本场数，整数 0–100 |
| `kyotaku` | 供托根数，整数 0–100；每根1,000点 |
| `scores` | 起家东、南、西、北的四个点数，均为100的整数倍，范围−100,000至1,000,000 |
| `table` | 可省略，默认`特上`；支持`一般`、`上級`、`特上`、`鳳凰` |
| `dan` | 可省略，默认`四段`；支持新人、9級至1級、初段至十段 |
| `custom_pt` | 可省略或为null；否则必须且仅含`first/second/third/fourth`四个整数，每项−1,000至1,000；覆盖想定卓与段位 |

`scores` 的索引是固定起家座位，不是每局轮转后的自风；本局亲家为 `kyoku_idx % 4`。负数点数可用于研究假设局面。输入范围是计算防护范围，不表示所有输入都对应合法实战状态；引擎不校验总点数守恒约束。布尔值、非整数、无穷值、缺失必填字段和未知 pt 预设均会被拒绝。Python API 也接受 `PtTable` 对象；跨语言接口使用 JSON 对象。整数指的是数值而非文本写法，因此`0.0`、`2.5e4`等整数值JSON写法也被接受；Python会复制并规范化输入，不改动调用者传入的对象。CLI的文件与标准输入统一按UTF-8读取，可带UTF-8 BOM，输出及错误也统一为UTF-8。

## 顺位概率

令温度 `T = 2000 × max(8 − kyoku_idx, 1)`。按 Plackett–Luce 模型计算四家最终顺序的24种排列概率，每次从尚未分配顺位的玩家中按 `exp(score / T)` 的相对权重选出下一名。

实现中每一步都先减去剩余玩家的最高分，再求指数，避免极大分差导致溢出或使余下顺位失真。将24种排列汇总得到 `rank_prob[seat][rank]`，每行与每列的和均约为1。此处“剩余局数”不考虑连庄次数、西入概率或牌力，是模型温度的简化参数。

四家同为25,000点的东1，四个顺位均为25%。默认 pt `[75, 30, 0, -90]` 对应每家期望 `3.75 pt`。平均顺位等于 `Σ probability[rank] × (rank+1)`；pt期望等于 `Σ probability[rank] × pt[rank]`。pt合计并不要求为零。

## 160项代表性结局

| 结局 | 枚举方式 | 数量 |
| --- | --- | ---: |
| 荣和 | 4名和了者 × 3名放铳者 × 9个点数档位 | 108 |
| 自摸 | 4名和了者 × 9个点数档位 | 36 |
| 流局 | 四家分别听牌/未听的全部组合 | 16 |

子家档位：1,000 / 2,000 / 3,900 / 5,200 / 8,000 / 12,000 / 16,000 / 24,000 / 32,000。亲家档位：1,500 / 2,900 / 5,800 / 7,700 / 12,000 / 18,000 / 24,000 / 36,000 / 48,000。

- 荣和：放铳者支付档位点数与每本场300点；和了者额外取得桌面供托。
- 自摸：档位作为**等价总点数**。亲家和了时三家各付总额的三分之一；子家和了时亲家付二分之一，其余两家各付四分之一；各笔向上取整至100点，每本场另付100点。故实收总数可能高于档位；这不是按符番精确推导的正式支付表。
- 流局：1/2/3家听牌时分配3,000点罚符；全听或全未听时无点数转移，供托保留。
- 和了结局中，四家点数变化之和等于取得的供托；流局为零。

160项是所选点数档位下的代表性枚举，未覆盖全部麻将结局，也不包含每种结局的发生概率。不要将160项取等权平均当作策略期望，也不要把某个局后顺位概率当作该结局的和牌率。

## 局面推进与终局

亲家和了或流局时亲家听牌则连庄；流局本场加一，和了连庄也加一，子家和了则本场归零。和了后供托归零，流局时供托保留。

采用以下简化终局条件：当前局为南4或之后且结算后最高分至少30,000点，则结束；西4无条件结束。这包括亲家连庄的结局，未实现正式规则中的和了止、听牌止等分支。终局时按点数降序确定顺位，同分按起家东→南→西→北优先；输出顺位为确定性分布，pt为对应顺位的确定值。终局的 `next_state.kyoku_idx` 保留当前局，始终不超出0–11。终局后的本场/供托字段为结算记录，不再表示可继续对局的状态。

未终局时使用下一局状态重新估计顺位和 pt。输入防护范围不会截断结算结果；边界输入可能产生大于100的局后本场数或超出输入点数范围的结果，不应直接当作有效的下一次输入。

## 输出契约

- `rank_prob`：当前局面的4×4顺位分布。
- `pt_ev`：当前四家的pt期望。
- `endings`：160个对象，包含`kind/winner/loser/base_score/tenpai/deltas/next_state/rank_prob/pt_ev/ev_diff`。
- `kind`取`ron`、`tsumo`、`ryuukyoku`；不适用的参与者、档位或听牌组合为null。
- `ev_diff`为局后pt减去当前pt，不是货币收益或策略胜率。
- 网页JSON导出增加`schema_version/model/request/result`外层，CLI和函数API直接返回计算结果。CSV包含输入、四个pt、各结局的转移、局后状态、16项顺位概率与pt变化；导出始终覆盖全部160项，与页面筛选无关。CSV座位编号为0–3，`rank`编号为1–4。

## 规则表来源与限制

内置pt取自[天凤官方手册「段級位制」四人東南戦](https://tenhou.net/man/#DAN)，常量位于`rankpt/rules.py`和`src/domain/rankpt.ts`。只替换pt表不能把整个模型改为东风或三麻，局数与终局逻辑也需要配套修改。

本模型未读取手牌、牌河、牌山、玩家实力或真实历史训练数据；未实现飞人结束、途中流局、多家和了、罚则、全部符番点数、终局剩余供托分配等完整规则。输出为可解释的局面近似，适合教学、可视化和策略研究，不能当作经过胜率校准的预测或正式结算器。

`npm run test:parity`对7组固定案例、覆盖全部12局的100组固定种子案例以及8组原始JSON边界案例逐字段比较两种实现，检查原始JSON的接受/拒绝一致性，并涵盖每个有效输入的所有160项结局，数值绝对误差上限为`1e-12`。跨实现一致性说明移植一致，不证明启发式概率等于真实对局概率。
